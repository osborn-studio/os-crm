# 钉钉本机同步：组织与人员

本批提供本机DWS授权桥接，与“企业应用接口（高级）”的AppKey/AppSecret接入分开。参照本机WorkBuddy的组织对照设计；未修改HR工程，不引入薪资、考勤或完整HR模块。新能力目前只允许管理员通过业务HTTP/UI调用，未开放委托智能体写入。

## 安装与配置

服务器需安装并完成官方DWS CLI登录，使用运行CRM的同一系统用户。新机器须独立授权，源码和备份均不携带DWS登录凭证。原Docker部署未捆绑DWS，不能把本机验证当作Docker钉钉接入已通过。

本机安装管理员执行 `node deploy/bind-dingtalk.mjs 公司编码`。需要时通过服务器环境的 `DWS_BINARY` 指定DWS可执行文件绝对路径。命令只在公司名称精确匹配且有唯一 `isOrgCurrent=true` 的账号时绑定，拒绝默认选第一个或静默改绑。配置写入该公司本机私有文件；重启该公司服务后生效。公司业务管理员不能通过HTTP更换企业、读取其他公司授权账号列表或指定可执行程序。

进入“集成与同步 → 钉钉本机同步”：

1. 确认服务器绑定状态，启用组织同步。此时尚未导入数据。
2. 点击“读取企业组织与人员”。后台读取，页面显示读取状态；服务重启将未完成任务标为中断，需要重新读取。
3. 核对企业名称和授权人，逐项选择新建、已有记录或本次跳过。根部门代表公司，不重复建一个公司部门。
4. 多部门人员明确选择一个已导入的CRM部门，或选择“暂不分配部门（保持停用）”，之后由管理员核定。系统不把返回数组的第一个部门当主部门。对应已有人员时保留原部门。
5. 核对并确认导入。整批部门、人员、对应关系、结果和审计在同一事务中提交，失败整体回滚。相同请求重放不重复创建。
6. 新账号默认“销售、停用”，随机未知口令不返回。管理员在人员管理核对角色、部门并设置新密码，再启用账号。不会发送员工通知。

对应已有人员只建立一对一关系，保留其姓名、部门、角色、密码、状态、会话及客户归属；不会把钉钉管理员身份转成CRM管理员。已建立的关系不在批量导入中改绑。同一本地记录不能合并对应多个外部记录，同名人员必须人工核对已有记录或跳过。同一上级的同名部门不能重复创建。跳过上级时须同时跳过其下级。

## 完整性、边界与证据

每次预览固定核对服务器绑定的企业和授权人。按部门广度遍历，发现与已访问分别记录，包含根部门挂靠人员，并补充人员详情。200部门、20层、500人员、1000调用及8分钟预算；遇到失败、循环、未消费分页或超预算明确记录 `complete/hasMore/stopReason/failures`，不允许导入不完整结果。

“完整”表示当前授权可见范围的本次读取未发生已知失败，不保证该账号拥有企业全部通讯录权限。读取无权限、未返回或失去可见范围的记录，不会导致本地删除、停用或收回权限。预览30分钟有效；仅一个进行中的公司组织任务，授权绑定变化、停用、已导入、过期均阻止提交。开启同步目前是允许手动预览/导入，不代表自动定时任务。

数据库新增三表：`integration_connections`、`integration_runs`、`integration_mappings`，各公司的记录仍在各自独立MySQL数据库内。迁移只新增表，不改写旧业务。完整预览与人员名称仅在企业数据库/本机私有验证目录；不得发布GitHub。成功回执仅记录数量，口令与外部授权凭证不进入回执、审计或代码仓库。

能力目录：`GET /api/v1/integrations/dingtalk-bridge/schema`。配置、预览启动和导入能力均1.0，共享当前身份/会话、管理员校验、事务命令与审计；JSON体不能提供租户或执行人。

## 本批验证

- Node24工程类型、lint、自动测试及构建：以本批PROGRESS最终记录为准。
- 独立真实MySQL、合成外部CLI协议：65项检查通过。覆盖多层部门、根/叶成员、显式关联、停用销售创建、权限与密码保持、失败回滚、跨帐套、重复请求、已导入任务不被旧预览请求覆盖、停用和审计。外部CLI为合成协议，此项不是企业联调。

## 下一批
