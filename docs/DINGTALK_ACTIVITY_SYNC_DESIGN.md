# 钉钉日程与审批待办：工程设计和验证边界

本批已在客户分配/权限之后实现日程对象、页面、本人配置、审批节点扫描和持久队列，并完成已授权正式公司本人端到端验证。本文保留前期设计的论证与阶段记录；当前操作、限额及已实现边界以[操作说明](DINGTALK_ACTIVITY_OPERATIONS.md)和进度顶部为准，不将下文早期计划的“拟新增/尚未”当作当前状态。

## 对象与方向

|对象|CRM主记录|钉钉投影|决定权|
|---|---|---|---|
|组织|部门/人员与持久对照表|只读通讯录来源|管理员逐项核定，不覆盖既有角色和客户|
|日程|拟新增独立日程对象，明确开始、结束、负责人和时区|授权本人主日历的日程|显式预览后发送，冲突不静默覆盖|
|审批待办|当前有效审批节点，包含会签中的各自节点|对应处理人的提醒待办|审批决定始终在CRM；钉钉完成状态不能代替批准/拒绝|

行动计划只有截止日期/时间，不具备会议持续时长；不能不经确认把它强行当作已有CRM日程。新日程页应提供月/周/列表、个人日程新建与改期、同步状态和跳转入口，先支持简单单次事件，循环、会议室和跨人邀请另行建设。

## 身份和对照

公司固定DWS授权已绑定已授权正式公司。第一批日程/待办仅作用于授权本人及其已核对的CRM人员，不能凭管理员身份操作其他员工私人日历。其他员工须增加自己的授权与唯一对照，未授权显示未连接，不借用管理员账号发送。

实测：通讯录员工userId与待办内部执行者ID不同；执行者名字相同不能证明身份。使用固定profile先核对公司/员工身份，再由`todo +get-my-tasks --all`的完整本人执行清单确认目标taskId唯一存在，同时要求详情只有一位执行者。分页不完整、身份不符、目标多匹配或多执行人均拒绝继续。

## 发送和对账

- 配置页分别提供日程、审批提醒开关，展示授权人、CRM人员对照、时间范围、最近运行与失败原因。首次不开自动推送。
- 本地事务先写持久发送记录：来源类型/编号/版本、目标身份、稳定标记、操作、字段快照和幂等键；外部调用在数据库事务之外执行。
- 状态区分待发送、发送中、已验证、结果不确定、明确拒绝；发送中重启归不确定，不自动重新创建。
- 创建必须保存远端稳定ID。改期/完成沿用原ID；超时或读回失败先对账，不能用“重试”生成第二条。
- 写后核对标题、时间/忙闲、待办状态及归属。更新接口可能没有结果对象，只要结构化成功仍须读回，不把空返回当作未执行而重发。
- 本地源记录在派发前重新验权和核对版本。审批转审/撤回/结束后关闭旧提醒，再为当前合法处理人建立新提醒；外部提前完成仅记录差异，不能修改审批节点。
- 日程取消优先设计显式状态同步，不默认删除外部资料。外部删除须明确授权。
- 外部标题/描述仅使用必要业务摘要和来源标记，不同步客户附件、密码、完整敏感审批表单；跳转地址使用已配置的LAN/HTTPS入口，不默认向手机发localhost。

## 已完成的协议层

`apps/api/src/modules/integration/dws-activities.ts`提供固定授权本人日程创建/改期及待办创建/完成的适配与字段回读校验；无HTTP接口、定时任务或智能体自主写入口。覆盖通讯录数组/对象响应、内部执行ID差异、完整清单证明、稳定ID、写后字段不符、不确定状态、禁止自动重试、无多执行人和无跨公司写入等单元反例。

真实测试资料及远端ID只保留本机私有目录，公开代码与文档不包含身份编号、凭证或其他员工信息。测试标题统一“【测试】”，日程为单次、不邀请其他人、不占用忙闲；待办只给授权本人。已授权正式公司授权本人实测通过：测试日程2026-11-16从12:00—12:10改期为12:10—12:20，标题、描述、时间及free忙闲均回读一致；测试待办创建后在本人完整执行列表唯一匹配，随后完成并回读isDone=true。未修改CRM审批状态、未邀请其他员工。单元测试15项通过；工程检查306项API、4项安装/加密、19项配置及类型/lint/build通过。此处是实际外部接口验证，仍不代表CRM页面端到端同步完成。
