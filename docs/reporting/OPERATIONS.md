# 销售预测、分期回款与统计操作说明

## 使用顺序

先维护部门、员工和商机阶段，再录入真实客户与商机。商机填写金额、预计成交日、下一步及负责人；未知成交日留空，报表会列为待确认。报价不是签约，签约不是到账，到账不是会计收入或利润。

合同填写实际金额与关联对象，提交配置好的审批流程。审批通过后点击签约，填写1—24期付款计划，每期金额、到期日、付款条件必填，合计须等于合同金额且日期按先后排列。系统不再自动生成30天全额计划。精确到分；非法金额/日期、合计不符、旧版本、重复生成和非开放关联商机会被拒绝。合同状态、商机赢单及全部分期在同一事务内保存，重复同一请求不重复建计划。`contracts.sign`契约升级2.0；旧客户端必须补充`paymentSchedule`，没有兼容隐式条款。

本地收款先登记，由另一名管理员复核后进入到账统计；核销把款分配到应收计划，不新增到账。核销撤销、登记更正及作废通过现有台账流程保留历史。银行和税务接口未开通，不能用本地收款台账代替真实银行对账或税务凭证。

## 销售预测

菜单“销售预测与回款分析 → 销售预测”。选择年份、全年或月份，可按可见负责人和部门收窄。卡片点击切换明细范围；明细下拉可看开放、已赢、已输、关闭或待确认成交日商机。

- 开放商机：预计成交日期在所选期间的当前开放金额。
- 阶段加权：逐笔当前金额×有效阶段概率，按分舍入后汇总。
- 已赢单：真实关闭日期落入期间的赢单额，不能再计入开放管道。
- 赢单率：赢单数÷关闭数；没有关闭商机时显示无数据。
- 停用/未知阶段不加权；缺日期和异常项单列，不能默认补进当前月份。

月度趋势、负责人和阶段分布与商机明细使用相同权限和计算口径。阶段加权属于规则计算；人工Commit提报、主管调整、锁期快照及机器学习预测仍未实现。

## 回款、应收与项目矩阵

切换“回款、应收与项目矩阵”。默认本地管理台账，历史只读来源单列，二者不混加；新正式帐套没有历史样例记录。

期间计划按付款计划到期日，期间到账按已复核收款到账日。页面同时列当期到账的已核销/未核销部分。当前余额、逾期和账龄是生成时的全期间存量，不是假定历史月底余额。账龄为未到期、1—30天、31—60天、61—90天、90天以上。

项目矩阵按合同展示全年12个月“计划/实收”两列，滚动可看完整年度。负责人汇总、计划/收款/当前余额/逾期明细可核对；未绑定合同的款独立待分配，不强行归属销售。只支持CNY汇总，其他币种排除并提示数量，不按未知汇率折算。

导出按钮明确仅导出当前页，不代表全部记录；合同矩阵CSV包含12个月的24个计划/实收字段。超过10000条读取预算会拒绝并提示收窄范围，不静默截断总数。读取失败清空旧结果并提示，避免把上一期间数字当作本期。

## 权限与AI调用

销售看本人、主管看当前团队、老板/管理员按授权看公司范围；负责人和部门筛选只会收窄权限。统计读取还检查实时会话、角色、合同与收款可见范围，不能通过请求正文传入执行人或企业身份。

只读HTTP能力：`report.sales.forecast@1.0`、`report.cash.collections@1.0`，在`GET /api/v1/analytics/schema`取得契约。AI集成可以调用这两项受认证API，并取得版本、口径及生成时间；尚未加入独立委托MCP工具目录。现有AI工作台摘要仍由规则生成；已有委托、人工批准、共享执行及回执机制不等于大模型已接通。

## 本批证据与限制

`pnpm check`通过：244项API测试、4项安装/加密测试、15项帐套/配置测试；包括金额与日期边界。真实MySQL：报表55项、公司隔离40项、客户合同306项、收款326项，各组独立测试库。分期包含缺少条款/合计不符拒绝、两期跨年金额、同请求并发只生成一次。没有把测试数据写入正式公司。

正式帐套客户、联系人、线索、跟进、行动、商机、合同、订单、项目、任务、付款计划、收款、开票记录、审批、流程、售后16类业务计数均为0；只有必要安装主数据和一个管理员。旧样例库先加密备份并认证后退出，测试库保留。

当前按实时归属和余额统计，无法重建历史业绩归属或历史余额；催收承诺、未签项目现金情景、目标配额、提报调整、收入成本毛利、退款、跨币种、真实开票与银行对账仍需后续建设。完整商用业务、安全、容量、移动端及灾备验收尚未完成。
