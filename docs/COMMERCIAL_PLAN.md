# 本地商用建设与验收计划

2026-11-01：用户将目标从演示版扩展为可以本地安装的商用 CRM，要求逐步补齐全部闭环，每次较大改进后同步 GitHub。主仓库为 osborn-studio/os-crm；每批使用功能分支和 PR，保留已经交付的演示版本。代码公开不等于生产验收。

## 产品原则

一个企业可以在自有服务器独立运行，数据、账号和备份由自己掌握。演示安装和正式安装使用不同配置、Compose 项目及数据库卷。正式初始化不注入演示客户或共享口令。已经公开的历史演示配置属于演示材料，不能用于正式安装。

业务服务负责权限、状态、事务、幂等、版本和审计，网页、HTTP 与智能体调用同一服务。智能体执行必须有独立身份、限时委托、明确能力范围、预演、执行回执和撤销路径。外部平台失败可重试和对账，不能把请求发出当成业务完成。

## 每批的发布门槛

1. 更新能力契约、业务状态与错误边界；新业务入口不能绕过权限及共享服务。
2. 完成类型、lint、自动化测试和构建；涉及数据的改动额外运行独立真实 MySQL 检查。
3. 更新 PROGRESS、限制和操作文档，按变更范围执行 Docker、升级或恢复检查。
4. 推送 osborn-studio/os-crm 并建立可审阅 PR，查看实际 CI。不得将失败或尚未运行的 CI 写成通过。
5. 形成发布候选包及校验值；产品负责人验收后再合并和正式发布。未经批准不部署到公网或客户生产环境。

## C1 的明确边界

正式模式启动与恢复是部署基础候选，不代表整套系统已商用就绪。正式初始化仍只创建管理员与四种角色，其他账号通过 C2 人员管理创建。备份第一版限制 SQL 导出小于 128 MiB，不含尚未建设的附件对象存储；升级跨版本恢复先使用备份对应的源码版本。Linux Docker 以当前提交 Actions 实际结果为准；macOS/Windows Docker 需另外实测。当前财务、AI 和外部集成的既有限制仍然有效。
