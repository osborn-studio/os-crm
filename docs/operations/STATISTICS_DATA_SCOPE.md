# 统计人员范围与数据权限

## 产品规则

所有现行统计入口（工作台、商机阶段看板、销售预测、回款/应收/账龄及项目月份矩阵）同时使用日期区间和人员范围。按当前角色及数据范围进入：管理员、老板默认当前帐套全公司；部门/团队数据范围默认本部门及子部门；个人数据范围默认本人。显式选择本人仍只查本人。日期仍限制为2010年1月1日至2060年12月31日。

人员范围是筛选条件，不能授予权限。服务器将它与当前帐套、模块权限、原有逐条数据可见规则取交集。默认范围由当前授权决定；显式筛选同样必须授权；越权直接返回403，缺少必要编号、互相矛盾的参数返回400，不静默退回其他范围。

| 当前数据权限 | 可选范围 |
| --- | --- |
| 本人 / custom未授予组织范围 | 本人 |
| 部门 / 团队 | 本人、本部门及子部门人员、授权部门子树 |
| 全公司，或现有管理员/老板权限 | 本人、本帐套人员、部门、全公司 |

候选来自实时服务端查询；不同帐套的同名人不可跨库选择。人员展示姓名及唯一人员编号，停用人员保留标签，便于交接后核对历史业务。角色、部门或权限改变后的请求按新权限重新校验，不能用旧页面选项扩大范围。协作客户仍只按原授权访问，不因选中其负责人而得到该人的全部业务。

## 操作与归属口径

在日期选择旁使用“人员范围”：按角色默认公司/部门/本人；有权限才展示“全公司（当前帐套）”、人员及部门。切换后重新查询、清空旧结果并重置报表分页。汇总、漏斗、趋势、负责人汇总、当前页明细及当前页XLSX/CSV导出均使用同一结果。工作台和看板跳转业务明细时携带日期及人员范围；普通业务列表保留原有可见范围，可手动启用人员筛选。

| 指标 / 对象 | 人员归属 |
| --- | --- |
| 客户、商机、合同、订单 | 当前负责人 |
| 联系人 | 所属客户负责人 |
| 项目 | 销售负责人或项目经理；同一项目只计一次 |
| 任务、行动、线索 | 执行 / 分配人员 |
| 跟进 | 所属客户当前负责人（原作者不变） |
| 开票、回款计划、已绑定合同回款 | 合同负责人 |
| 未绑定合同回款 | 不强行分给某个销售，仅全公司统计可计入，并单独说明 |

这是当前归属下的统计，不是历史人员归属快照；当前未收、逾期、核销也不是历史期末余额。客户建档日、预计成交日、签约日、实际回款/开票日等日期口径见现有日期说明。

## HTTP与智能体契约

`GET /workspace/statistics-options`为只读候选查询，返回`defaultRange=company|department|self`及`defaultDeptId`、`selfId`、`canCompany`、`owners`、`departments`；不接收帐套/身份替换参数。

工作台、报表及用于钻取的业务列表支持：

- `personRange=self`，不附带其他编号；省略全部人员参数时使用当前角色授权默认范围。
- `personRange=person&ownerId=<唯一人员ID>`。
- `personRange=department&deptId=<部门ID>`。
- `personRange=company`，仅有全公司数据权限可用。

报表旧版显式`ownerId`或`deptId`分别按人员/部门范围处理并严格授权，不再把非法范围当作空结果。普通业务列表仅在显式`personRange`时启用统计筛选，保持业务操作列表语义。

人工MCP的`workspace.overview`、`workspace.list`、两类报表工具，HTTP报表能力及独立委托MCP共享应用服务和授权；省略人员参数时网页和智能体均按当前授权角色默认范围。独立委托仍受委托能力、预算、实时撤权及原委托人权限限制，不产生额外权限。

## 验收证据

本批真实MySQL合成场景验证报表92项、委托/官方MCP100项：四角色默认授权范围与显式本人选择、授权公司汇总、无权限参数注入、跨人员/部门/公司、工作台及列表钻取、未绑定回款、精确金额、查询上限、并发预算、读取中撤权与审计故障。界面和安装验证以本批实际记录为准；不据此宣称全系统商用验收。

## 关联数据规则

客户详情逐模块检查联系人、商机、合同、项目、跟进和行动权限，缺少读取权则不返回该模块。商机关联跟进也须满足跟进权限和客户可见范围；行动按执行人范围。合同内回款计划、开票及收款要求财务读取权；已绑定收款、核销明细沿合同归属过滤。未绑定收款按客户权限，个人回款统计不强行归属。审批历史按本公司/主管下属发起/本人参与范围读取；读取不授予代替审批权。

商机看板按100条分页，不再因全公司年度超过1000条而整体失败；阶段数量及金额明确为本页。完整汇总使用销售预测。历史预计日期可经管理员活动整理命令补齐，保留估算、依据、来源日期、行动关联、版本及审计，不补造实际成交日。

选择主管或部门负责人时，`personRange=person&ownerId=...`表示其经营责任范围：本人和其负责部门子树下的人员；候选明确标注“含下属团队”。普通销售仍只包含该人员。管理关系来自当前部门负责人和销售主管岗位，不把下属记录的ownerId改成主管；最后仍与调用人的逐条可见范围取交集。`personRange=self`始终只统计登录人自己，区别于其管理团队。公司管理员的全公司查看权限不等于把所有客户归其名下。

业务计划日程使用`origin=crm_plan`及稳定行动编号，老板/管理员可读本公司，主管可读管理范围，销售读本人；日程也支持相同人员范围筛选。其他人的个人手建和钉钉来源日程不因业务管理范围而公开。每项待办生成一个拟定30分钟工作时段，检查本人忙闲冲突；完成行动会在同事务结束相应计划日程。此类拟定计划不进入钉钉外发扫描，不代表客户确认会议或付款日期。
