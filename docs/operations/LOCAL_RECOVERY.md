# 本地整套备份、恢复与服务守护

本页为运维功能1.0操作契约。仅服务器本机操作员使用命令行；没有HTTP、MCP或智能体调用入口。不是把数据库Root权限交给普通CRM管理员。

## 能力与边界

|能力ID|输入|输出与效果|前置与限制|
|---|---|---|---|
|installation.backup 1.0|帐套目录、归档路径、独立密钥文件|AES-256-GCM认证加密的全公司SQL、必要解密密钥、逐表数量及附件Hash；独立回执|全部帐套ready、停止全部公司进程、最多10公司/总SQL128MiB；不覆盖旧文件|
|installation.restore 1.0|归档、原独立密钥、新目录、本机MySQL运维连接、入口端口|新数据库、新独立SQL用户、新配置及完整注册表；离线验证回执|先完整认证和版本验证；新目录必须不存在；绝不覆盖原库|
|installation.service 1.0|明确帐套目录、端口、当前构建路径|macOS登录启动、进程守护；公司工作进程独立退避重启|先构建及配置；安装前停止手工进程；Linux使用正式Docker的restart策略|

公司编码及现有密码保持；每家公司全表数量与附件内容Hash逐项核对后，才发布完整注册表。保留原数据加密密钥用于解密既有集成设置，JWT签名与备份密钥重新随机生成；所有旧会话与智能体委托撤销。日程同步开关关闭、待发送取消、发送中转为不确定；DWS人员/公司绑定和外网入口不继承，恢复后必须重新核定授权。

备份必须暂停业务写入。工具拒绝仍监听中的公司进程；也不能让其他数据库客户端在备份期间写入。每家公司SQL使用一致性事务，整个归档不是跨公司分布式事务。若数量或附件与归档不符，恢复失败，禁止发布注册表。失败新库保留供调查，不自动删除任何原库或失败库。恢复不是自动切换线上网站。

## 备份

先停止守护服务或手工网关，确认公司工作进程均已退出；MySQL保持运行。然后在版本匹配的工程根目录执行：

```sh
node deploy/local-recovery.mjs backup /安全备份目录/crm-20261115.crmbackup /独立保管目录/installation.key /安装目录/.local/accounts
```

首次生成随机密钥文件（权限600），后续复用同一文件。密钥与归档必须分别保管并有离机副本；丢失密钥无法恢复。归档本身包含必要数据解密密钥，只能交给有权恢复整个安装的操作员。不要提交到GitHub、发送聊天或放进公网下载目录。归档、回执均不覆盖旧版本。完成后可重新启动原服务。

## 恢复与核对

先安装与备份相同schema版本的工程、Node24、pnpm11和MySQL8，执行依赖安装、数据库客户端生成和构建。使用新的帐套目录；不需要先新建公司。

```sh
ACCOUNT_WEB_PORT=3200 ACCOUNT_BASE_PORT=4400 node deploy/local-recovery.mjs restore /安全备份目录/crm-20261115.crmbackup /独立保管目录/installation.key /安装目录/.local/recovered-20261115
```

本机已配套安装的MySQL3307使用私有运行环境凭证；其他本机MySQL由操作员通过私有环境设置`ACCOUNT_ROOT_DATABASE_URL`及必要的`MYSQL_BIN_DIR`。连接密钥不要写入命令参数或公开文件。正式恢复只授予127.0.0.1来源的公司SQL账号。

查看新目录`restore-receipt.json`必须为`verified-offline`且全部公司为`verified`，核对逐表数量、附件Hash及备份时间。`promoted:false`明确表示未替换原网站。失败状态没有注册表，启动器也拒绝把它当空安装使用；使用另一个新目录重新恢复，保留失败证据。

```sh
ACCOUNT_DIRECTORY=/安装目录/.local/recovered-20261115 ACCOUNT_WEB_PORT=3200 ACCOUNT_BASE_PORT=4400 node deploy/local-accounts.mjs serve
```

用原公司编码和现有密码登录，在新入口核对客户、合同、审批、应收、核销、角色与数据范围；旧登录凭证应拒绝。确认无误后再安排停写、重新备份与入口切换。恢复后新产生的业务不会自动合并回原库。不要同时把原站和恢复站用于正式录入。

## macOS守护服务

先停止同一安装的手工启动器。默认服务名`cn.tingmeng.tb-crm`；只在当前用户登录后启动，不承诺未登录时运行。

```sh
node deploy/local-service.mjs render
node deploy/local-service.mjs install
node deploy/local-service.mjs status
node deploy/local-service.mjs stop
node deploy/local-service.mjs start
```

服务使用当前Node绝对路径及已构建代码，不在重启时安装依赖或构建。配置没有数据库密码；公司进程仅取得本公司配置。网关被终止后由launchd重启，公司进程退出后按1、2、4秒逐步退避至30秒重启，其他公司保持运行。连续失败会保留日志，不伪装就绪。恢复服务或非默认端口可在上述命令前设置`ACCOUNT_DIRECTORY`、`ACCOUNT_WEB_PORT`和`ACCOUNT_BASE_PORT`，须始终使用同一组设置。

同一帐套目录使用进程锁拒绝重复启动；异常终止留下的已失效锁可恢复，活进程锁不会被覆盖。损坏锁或无法证明已失效时拒绝启动，交由运维检查，不任意杀进程。

升级先在候选目录完成检查和备份，停止服务，再构建及迁移，按版本启动验证。不要在正式服务运行时替换构建产物。先`stop`再`uninstall`只移除服务配置，数据库和帐套文件保留。

日志位于帐套目录`service.stdout.log`、`service.stderr.log`及各公司日志；需由操作员定期归档。当前没有自动日志轮转、跨机器灾备自动切换或RPO/RTO承诺。

## 已实际验证

隔离MySQL两个公司、丰富业务初始化846项；新增运维45项；备份前与恢复后各163项关系、金额、数据范围及隔离核对。包括非空附件、旧会话失效、独立SQL账号拒绝跨库、错误密钥/损坏归档/版本不匹配及跨库SQL在写库前拒绝；数量核对失败不发布注册表且禁止启动。实际公司进程SIGKILL后自行恢复，另一公司PID保持；macOS验收副本已安装launchd并在整体进程SIGKILL后恢复就绪。
