# 私有证据附件 · 第一批

项目、项目任务和售后工单详情新增附件区。文件只通过登录后的业务接口读取，没有公开文件URL；列表与审计只返回元数据，正文不会复制进命令回执、审计或MCP工具。当前不提供智能体上传/下载工具。

## 使用与权限

1. 在有执行权限的项目、任务或工单详情中点击“上传附件”。选择PDF、PNG或JPEG，核对来源与上传权利并勾选确认。
2. 单文件上限1MiB；文件扩展名和文件头必须匹配。系统尚未进行病毒扫描，文件只下载保存，不在CRM内直接执行或内嵌预览。
3. 列表展示文件名、大小、SHA256摘要与上传时间。下载时服务端和浏览器校验完整性，下载保存为文件；接口响应禁止缓存。
4. 上传人或管理员可在对象仍允许编辑时填写原因撤回。撤回不删除原件、不释放历史容量；保留撤回原因，只有仍具所属对象读取权限的管理员可追溯下载撤回原件。

管理员、项目经理及其部门主管可维护进行中项目证据；当前任务处理人可维护本人任务证据；售后项目管理人或当前处理人可维护未解决工单证据。仅有跨部门任务/工单协作读取不授予项目级附件编辑权限。老板只读。

## 验收与历史

项目正在验收审核时，项目及任务附件冻结；任务完成、项目完成或取消后也冻结。售后工单提交解决方案、关闭或取消后附件冻结，需先依业务流程退回重办。上传/撤回会同步改变父记录版本；旧页面不能在未刷新核对新增证据时直接提交完成/验收。

任务完成、项目提交验收、工单提交解决方案的不可变事件保存当时有效文件的ID、名称、大小及SHA256。重办后撤回文件不会改写这些历史快照；原件随历史保留。

所有附件写入使用共享AttachmentService、Serializable事务、实时会话/人员/权限校验与持久化幂等回执。权限撤销后，重放旧请求也不能绕过当前读取范围；并发上传不能突破企业容量。下载仅在企业/父对象范围与内容Hash验证通过后返回，并记录不含正文的下载审计。

## 容量、部署与备份

本批企业历史保留容量16MiB，每个对象最多100条附件历史，列表完整返回这100条。容量包含撤回记录；界面会明确拒绝超额上传，不静默截断或丢弃旧件。扩大容量与大文件对象存储需要另外做容量、性能、恢复与保留策略验收。

新增`202611010011_evidence_attachments`迁移，只新增一张二进制证据表，不修改原验收。文件以二进制保存在MySQL中，文件名不用于服务器路径。既有AES-256-GCM加密数据库备份同时包含元数据和原文件；恢复新库后重新登录，可验证原Hash并下载原件。备份SQL整体128MiB上限仍有效。加密备份不等于运行中数据库磁盘加密；主机/数据库磁盘保护由部署环境提供。

部署顺序：备份旧版本 → 停止旧API → 执行增量迁移 → 启动同版本API与网页 → 检查ready及角色读取。不要向已有库重播演示种子。恢复遵循PRODUCTION_INSTALL手册的新库恢复方式，不自动覆盖原库或提升到生产。

## 接口与验证

`GET /api/v1/evidence-attachments/schema`提供四个1.0版本JSON Schema契约、参数绑定、路由、权限、效果和证据：list、download、upload、withdraw。前端和后续受控适配器应调用同一应用服务，租户/上传人从当前身份获取，额外伪造字段被拒绝。

`pnpm check`覆盖文件名、文件头/扩展名、标准Base64和大小边界；独立`SMOKE_ALLOW_WRITES=true node scripts/attachment-smoke.mjs`仅允许tb_crm_test_*合成数据库，验证真实HTTP、跨企业/角色/协作权限、冻结、父版本、验收快照、故障回滚、并发容量、100条完整历史、二进制损坏拒绝与非空加密恢复。演练文件和项目明确为合成资料，不是客户签收。

仍待扩展：病毒扫描/隔离、大文件存储、容量配置、历史归档与保留策略、复杂格式/在线预览。当前目录中的原型ProjectDocument字段不自动变成新版证据附件，也不会根据旧文本虚构原文件。
