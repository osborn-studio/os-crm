# 个人日程与钉钉审批提醒

适用0.3.0候选。组织同步方向是钉钉→CRM；本说明的日程、审批提醒方向是CRM→已授权本人的钉钉。没有开启钉钉个人日程的自动批量反向导入，也不会在钉钉完成待办后自动批准CRM业务。

## 我的日程

从左侧“我的日程与同步”进入。月历、周视图、列表可切换；小屏默认列表，时间按上海时区显示。可按已安排/已取消/全部筛选。点击“新建日程”，填写主题、起止时间、地点、内容与忙闲；保存后只有本人可见，管理员和老板也不会因此获得其他人的私人日历。

销售/主管的日程查看、新增、编辑与“行动计划与个人日程”权限点一致；老板保持只读。单次日程最长31天，时间精确到秒；同一日程的并发修改只有一个版本成功。取消通过状态保存，不删除历史。

## 首次连接

公司管理员先按[组织同步说明](DINGTALK_SYNC.md)完成公司绑定和人员对照。授权读取人的既有CRM对应可直接用于本人日程；其他员工须先用各自钉钉账号完成本机DWS授权，再由服务器管理员绑定精确profile：

```sh
node deploy/bind-dingtalk-person.mjs COMPANY CRM_USERNAME EXACT_PROFILE
node deploy/bind-dingtalk-person.mjs COMPANY CRM_USERNAME EXACT_PROFILE --apply
```

第一条只核对。脚本验证profile的真实公司、员工身份和组织对应表，不根据同名猜测，不替换主授权，不更改员工密码、角色或客户。保存后重启公司服务，由本人登录网页开启自己的开关。没有员工本人授权时，网页显示未连接；不能借用管理员身份发给其他员工。

个人页面“本人钉钉同步”和管理员“集成与同步→本人日程与审批提醒”使用同一服务，均仅操作当前登录人的数据。配置页显示CRM对应、授权状态、最近扫描、错误和对应关系。

## 手工同步

1. 开启需要的“日程同步”或“审批提醒”，保存。日程需行动查看/编辑，审批提醒需批准和驳回权限。自动同步默认关闭。
2. 点击“扫描变化”，检查发送主题、起止时间、忙闲或待办目标状态。日程新记录范围为过去7天至未来93天；既有未归档对应继续跟踪。
3. 选择1—50条“加入发送队列”。此时没有外部写入；整批预备失败会回滚。
4. 在发送记录中点击“发送并核验”，确认对象。服务后台发送并回读，网页显示发送中、已验证、发送前拒绝或结果不确定；请求重复不会再次创建。

日程取消在原钉钉记录标注“已取消”并改为空闲，不直接删除。日程内容、地点与唯一来源标记进入本人日历；不预订会议室、不邀请其他参会人。发现外部已加入其他参会人时停止更新，避免把测试或个人更新扩散给别人。

## 自动同步

明确确认“每60秒自动同步”后，后台按当前人员状态、权限和保存的授权持续扫描，不依赖浏览器保持打开。每位人员每轮最多发送一条任务，已经发送的相同内容不会重复导出；JSON存储键顺序、其他人的会签决定和普通重新登录不会产生无意义重发。

人员停用或权限被收回后，不再派发不符合当前策略的任务。正常退出网页不会撤销已明确保存的自动同步授权；要停止后续推送，应关闭配置开关。已经发出的请求不能撤回，回执与历史保留。

本安装配置上限为100位自动同步人员，每人100条待处理发送、500条未归档对应；不是容量压测结论。达到上限会明确拒绝新任务，不截断成功。可处理队列或归档已结束对应后继续。

## 审批提醒的闭环

仅当前有效节点的实际处理人收到提醒。会签时每人有独立待办，一票通过不会代替其他人的决定；转审后关闭旧处理人的提醒，新处理人须使用自己的授权。撤回、驳回、结束后关闭旧提醒。

待办只传递审批编号、节点名称和来源标记，不传客户附件、完整表单或财务信息。审批决定在CRM完成。钉钉待办被人工提前完成，不会批准CRM，也不会生成合同、收款或其他业务结果。

流程设计器提供“停用”：拒绝新的提交，在途实例继续使用原快照；可重新发布同一版本。停用、发布均要求管理员、当前版本和审计。

## 冲突、故障和对账

- **发送前拒绝**：检查源版本、开关、人员状态及权限。修正后重新扫描预备；没有被证明未执行的创建不会直接重试。
- **钉钉端已有修改**：默认不覆盖。核对后可明确点击“以CRM为准覆盖”；该决定记录到回执。外部已取消或含其他参会人的日程不允许强制覆盖。
- **结果不确定**：可能已在钉钉创建，但返回或本地回执未完整保存。禁止点“重新创建”。点击“只读对账”，使用该条的钉钉记录编号；已知编号不能替换。系统核对本人归属、唯一来源标记、主题、状态与时间，完全一致才确认。
- **未知远端编号**：按主题里的唯一`[CRM:…]`标记在本人钉钉核对，取得真实记录编号再回读；不要选择同名的其他记录。
- **暂时无法核定**：可“停止本条同步”。这不代表发送成功，该来源也不会自动重新创建。之后可“恢复只读核对”；恢复不会重发。已停止的旧记录可在全部发送历史中找到。
- **业务已继续修改**：先对账旧发送快照，再扫描新版本，沿用同一个钉钉编号更新，避免重复日程。

服务重启把发送中任务标为不确定，超过10分钟没有终态的发送也进入核对；不盲目重放。外部已成功而本地审计事务失败时，只保留不确定状态与已知远端编号，不伪造成功对应或回执。

## 历史与归档

主表显示最近100条、待处理优先；“全部发送历史”按创建时间分页访问全部本人当前可见历史，其他公司和人员的游标无效。

归档保留数据库证据和钉钉记录，只停止对已结束来源的持续跟踪。仅已取消/结束超过7天的日程，或已处理的审批提醒可归档；未完成发送须先核定或明确停止。有新安排重新进入范围时，正常已归档对应可沿用原钉钉编号恢复跟踪；已明确停止的来源须先人工核对，不会自行创建。

## 备份与恢复

公司加密备份包含日程、开关、队列、对应和审计。恢复到新库后，所有同步开关关闭，待发送记录取消，发送中记录转为不确定，旧会话撤销。恢复副本不会继承自动发消息的许可。检查新库与对应来源后，由本人重新授权开启。

## 接口与智能体

`GET /calendar/schema`及`GET /integrations/dingtalk-activities/schema`提供版本1.0能力契约。个人日程、配置、预览、预备、派发、停止、恢复核对、归档和历史均有明确权限/效果/状态限制；网页调用同一服务。公司、执行人、profile不能来自请求体。后台仅使用有界的DingTalk系统策略，不能借此调用续费、锁期或其他系统命令。本批未开放独立智能体自主写日历或替人处理审批。

实际工程与真实MySQL、浏览器、已授权正式公司本人的外部联调结果以[当前进度](PROGRESS.md)和本批PR为准。本人验证不代表全部员工已授权、实体手机已验收或外网已联通。
