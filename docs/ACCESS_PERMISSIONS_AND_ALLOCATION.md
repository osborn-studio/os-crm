# 客户分配与功能、数据权限操作说明

本批适用于四种预置角色。管理员和老板保留固定职责，管理员可配置销售、销售主管的29个业务权限点和本人/本部门/全公司数据范围。任意自定义角色、逐字段权限、选定多个部门和逐人独立覆盖尚未开放。

## 为人员配置权限

1. 管理员进入系统管理 → 用户管理，建立部门并为人员选择部门及一个角色。
2. 点击人员行的“有效权限”，核对角色、数据范围、业务权限和名下客户数量；“名下客户”可跳转分配工作台。
3. 点击“配置所属角色权限”，或进入功能与数据权限页，选择销售/销售主管，调整查看、新增、编辑及特殊操作，再选择数据范围。
4. 保存前核对受影响人员数量。配置作用于该角色全部人员，成功后撤销他们的旧会话，要求重新登录。存在待办审批或未完成交付职责时，部分撤权会被拒绝，应先交接职责。

本人范围按当前负责人计算；本部门是直接归属部门，不递归包含子部门。全公司范围仍需要相应功能权限。公海可见、显式共享和审批协作保留既有规则。销售即使获得全公司查看范围，也不会自动拥有主管分配职责。新增、编辑依赖查看，关联销售业务依赖客户查看，回款统计依赖合同查看。页面菜单、直接HTTP、共享业务服务及现有智能体授权采用相同有效身份计算；隐藏菜单之外，后端仍独立拒绝越权请求。



## 给人员分配客户

进入客户经营 → 客户分配工作台。可按客户名称、原负责人、公私海筛选，支持从人员页反查名下客户。勾选本页1—50个客户，选择接收人并填写原因，点击“预览分配影响”，核对前后负责人后确认。

接收人须启用、拥有有效部门及客户查看/编辑权限的销售。销售主管仅能选择本部门接收人，且只能处理自身当前数据范围内客户；管理员可跨部门分配。钉钉新同步的停用人员不自动进入候选名单。

批次整体提交或整体回滚，提交时重新核对客户版本、接收人资格与可见范围。客户负责人、部门、公私海、保护期和私海持有记录一起更新。存在商机、合同、订单、项目或已转化线索的客户，必须进入“客户导入/销售交接”执行整体交接，不能仅换客户负责人。

最近50条历史只显示当前有权查看的客户；缩小范围后旧回执和历史不会继续暴露失去权限的客户。旧版本没有保存前后归属明细的历史不伪造补齐。



## 调岗、停用与离职

人员仍有名下客户、商机、合同或订单时，停用/离职、改部门或撤去销售身份会被拒绝。先完成客户分配或整体交接，再处理项目经理、任务、审批和售后职责。历史停用人员的资产仍可由有权限的管理员/主管检索并交接，但他们不能接收新客户。

## AI调用与能力契约

`GET /system/access-policy/schema` 提供角色配置与人员有效权限契约；`GET /customer-allocation/schema` 提供批量预览和提交契约。执行人及公司来自认证上下文，不接受请求体伪造。网页与后端使用相同服务；本批高影响管理写入未开放为智能体自主写工具。既有委托智能体每次调用重新检查授权，不依赖发证时快照继续越权。
