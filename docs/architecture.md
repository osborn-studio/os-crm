# Architecture baseline · 2026-10-31

## 2026-11-01 commercial construction update

C7 adds opaque delegated credentials separate from human JWTs, server-keyed HMAC storage, parent-session/owner-permission snapshots, bounded lifetime and admitted-call budgets. The agent HTTP/MCP adapter exposes only two restricted customer reads plus action proposal/execution; human controls cannot be invoked with an agent credential. A proposal retains immutable normalized input and a customer version, expires within 30 minutes, and requires the original human owner's decision. Execution rechecks target and delegation inside the shared Serializable command boundary even before replaying an existing receipt. Web and agent action creation share WorkspaceService; one proposal cannot create duplicate actions. Human compensation can cancel a still-visible, uncompleted AI action without deleting original input, decision or execution. Read results are not cached; read audit links and success/failure write evidence preserve provenance without raw credentials. Nonempty encrypted recovery verifies all three agent tables, actions, commands/audit and rejects old credentials after signing-key rotation. Model calls, expanded object delegation, service-account/OAuth flow and complete agent operations remain unfinished. See AGENT_DELEGATION_OPERATIONS.md for task contract, permission/state matrix and validation boundaries.

C6 transfer appends a successor at the original node position, marks the previous node transferred without changing its assignee or the immutable form/flow snapshot, and advances the current pointer only when transferring the current node. The assigned approver may transfer only their current node; administrators may recover future pending assignments for offboarding. Targets must be active same-tenant users in active departments with both decision permissions and cannot be the applicant or old assignee. Transfer never approves a document or invokes its business callback. A live-session Serializable command atomically preserves node changes, append-only actor/name evidence, inbox notifications and idempotency receipts. Approval history and events use cursor pagination and participant/admin visibility. Populated encrypted recovery verifies original/transferred nodes, snapshots, events, notifications and command receipts before authenticated clone reads. Parallel countersign, add-sign and external notification delivery remain unfinished.

C5.1 adds explicit receipt correction under immutable voucher identity. The original receipt retains its unique bank-reference fingerprint; a tenant-scoped voucher tracks its sole current receipt, and a unique predecessor link prevents forks. Only a managed current receipt without active allocations can be superseded. Correction creates an unconfirmed successor, voids the prior entry without rewriting its financial fields or losing original void history, and appends both audit events atomically. Current/target contract approval guards, version checks and independent re-confirmation remain enforced. Administrator/boss read projections can follow audit chains; sales/team projections redact correction snapshots, cross-customer notes and predecessor pointers, including shared Workspace/MCP reads. A populated C5-to-C5.1 upgrade test preserves old data, backfills voucher roots without events, performs correction, then checks encrypted new-clone recovery and session rotation for the nonempty financial chain.

C5 introduces a managed local receipt ledger separate from legacy/demo records. Registration fingerprints canonical external references, requires another administrator to confirm, and uses exact Decimal allocations against same-customer and optional bound-contract plans. Receipt, plan and contract balances are reconciled before writes and atomically updated with append-only finance events, durable command receipts and audit. Reversed allocations remain present with inactive status; voided receipts retain history and cannot be reused. The old allocation pair uniqueness is replaced by indexes so subsequent allocations and reversals remain distinct. Current operations are administrator-only manual CNY bank-transfer records, not bank verification, money transfer, tax/accounting integration, refund or receipt correction. Existing scoped read-only MCP can read allocation/event evidence through WorkspaceService. Finance HTTP contracts are versioned and do not expose agent writes.

C4 adds append-only delivery events, started-project task guards, exact cumulative task hours, milestone/task dependencies, explicit acceptance submission, mutation freeze during review, independent manager/admin review and rejection/remediation. Reopening a completed task resets dependent milestone completion while preserving historical evidence. Parent project timestamps are touched by task mutations to serialize acceptance against task changes. Project managers can see project tasks; task-only supervisory writes additionally recheck parent project scope. Text evidence is not attachment storage or external customer signature. New project/task action contracts are version2.0; agent writes remain disabled.

The delivery staffing increment adds manager handover with atomic unfinished-work transfer, task assignment, actor-name evidence snapshots and offboarding/department/role-change guards. Explicitly assigned unfinished tasks grant project read collaboration, not project management; management operations separately recheck PM or departmental sales/PM authority. Completing the last collaborative task removes that read basis. Candidate users require active departments and project read/update permissions; cross-department delegation requires administrator authority. Historical authors/completed executors stay unchanged. Compatibility migration repairs only built-in sales definitions with existing order/project create-and-read paths; production initialization uses the corrected definitions.

The product owner authorized incremental construction toward a locally installable commercial system and GitHub synchronization after significant, verified batches. This is a target, not a production-acceptance claim. See COMMERCIAL_PLAN.md for C1–C9 acceptance gates.

C3 introduces durable actor/tenant-bound CSV previews, canonical-name uniqueness including legacy rows, atomic public-customer import and complete sales-ownership graph handover with graph-digest revalidation. Delivery managers, task executors and historical authors are not implicitly reassigned. Immutable quote versions and selected contract quote snapshots preserve pricing provenance. Contract change requests carry server-authored before/after approval evidence and apply only after the shared approval callback rechecks the source version and downstream/financial guards. Unsupported downstream compensation is rejected explicitly. Successful login now takes an atomic conditional user-row lock in ReadCommitted before issuing a session; this avoids cross-user serializable session-range deadlocks without allowing stale password/status checks. Refresh replay handling remains Serializable.

C2 adds durable server-side sessions with refresh-token hashes, absolute session expiration, rotating one-use refresh tokens and replay revocation. JWTs must carry a currently active session ID; old sessionless tokens fail closed after migration. Personnel commands share the transactional command runner, reference and version checks, tenant-row serialization, last-administrator and pending-approval guards, and session revocation. System role-definition writes remain disabled until custom role policy is reviewed. Identity contracts are machine-readable but not exposed as agent write tools. Account-scoped persistent failure limits are not a substitute for ingress traffic controls or MFA.

C1 introduces a separate production Compose project/volume, independent generated secrets, empty-organization transactional initialization and company-code login. Initialization creates only an administrator, four roles and reference settings, refuses occupied/demo databases, and does not reset users on restart. Deployment-only installation commands are not agent capabilities and expose no HTTP route.

Encrypted backup uses a MySQL consistent snapshot, compression and Node AES-256-GCM with a separate operator-held backup key. Restore authenticates before writing, checks the schema fingerprint, only creates a new database, preserves the original and never automatically promotes a clone. Recovered application encryption keys are retained; session signing keys are rotated. The initial SQL limit is 128 MiB, with no attachment storage or cross-version restore automation. Native MySQL integration and Linux Docker are distinct checks; platform claims require their actual results.

## Product contract

The product owner authorized AI-assisted construction of tb-crm, with business information and operations accessible to agents. Keep the existing NestJS/React/MySQL direction. This baseline evolves the Qwen prototype incrementally.

## Layering

Web / future MCP adapter → versioned capability registry → application services → state/permission/transaction rules → Prisma/MySQL.

The `capabilities` HTTP adapter currently exposes only `customer.search@1.0` and `customer.get@1.0`. Actor identity is a currently authenticated human user. This is not yet delegated agent authentication. Listing is permission-filtered; invocation validates inputs again and records an execution UUID and outcome. Results are restricted projections without phone/bank/attachment data. Read retries may create new audit entries; write idempotency is not implied.

Customer list/detail and tool queries use the same CustomerService and customerVisibility policy: all scope sees all; dept/team sees public, own and department records; custom defaults to own/public until explicit grants are implemented. Other prototype services have not yet received equivalent record-level review.

## Query boundary

JWTStrategy rejects refresh-as-access tokens and reloads the active user, tenant and role permissions. Global guards protect all routes except explicit @Public handlers. Missing tenant IDs are rejected by forTenant(). Model metadata determines whether deletedAt exists; findUnique is filtered before lookup. Raw system transactions and nested association writes still require per-action review; the extension is not a blanket proof of tenant isolation.

## State and effects

Contract signing and order confirmation now require approved state. Approval callbacks, milestone-payment coupling and full atomic business commands remain pending. No financial write capability is exposed to agents. Introduce a persistent command execution record, idempotency key, expected version and transactional outbox before adding such tools.

## Runtime choices

Node.js 24 and pnpm 11.25.0 are pinned to the available runtime and generated lockfile. Prisma remains on the prototype's major version 6. HS256 is retained for the local baseline, with a separate random JWT_SECRET; production key management is pending. No specific model SDK is required for business capabilities.

## Verification boundaries

HTTP tests use a mocked DB and real NestJS routing/guards/JWT verification. Query-extension tests inspect generated query constraints. MySQL migration/seed/boot/customer+tool smoke is a separate CI job. No production deployment, external system sync, commercial acceptance or comprehensive security certification is established by these checks.

## Known inherited debt

Prototype modules retain untyped DTOs, incomplete row/field permissions, incomplete receipts/approval/event chains, unreviewed raw transactions and missing business tests. Legacy lint exceptions are explicit in eslint.config.mjs; new capability/filter/types code prohibits explicit any. The original 70% overall coverage goal is not achieved by this first baseline.

## v0.2 demo implementation update

The active web adapter now uses WorkspaceService, with a machine-readable resource/operation registry at /workspace/schema. It enforces current role permissions and record scopes, validates allowed fields/references, and wraps writes in Serializable transactions with durable CommandExecution results, payload hashes, expectedUpdatedAt checks and audit records. CustomerService's compatibility read projection and WorkspaceService use the same customer visibility function and current team membership. Legacy business controllers return503 and are excluded from OpenAPI; legacy cron is disabled by default.

The approval designer stores versioned draft definitions, publishes immutable versions, resolves required approvers without auto-approval, snapshots fields/nodes, and processes only the current node. Contract, order and project callbacks run in the same transaction. Form requirements are resolved server-side from the actual document and rendered on submission. Project drafts/rejections are explicit states. Missing/ambiguous approvers, self approval and invalid amount conditions fail closed.

Stateless MCP Streamable HTTP uses maintained SDK v1 (protocol up to2025-11-25). Each request reuses its currently authenticated human Actor; seven read-only tools call the same business services. No independently delegated OAuth identity or agent write tools are supplied. DingTalk/Feishu platform requests are separately tenant-bound and remain unverified against a real enterprise until credentials and scopes are configured.

Finance is deliberately presentation-only at this milestone, as directed by the product owner. Seeded receipts, invoices, plans and allocations are synthetic. Demo replay creates a fresh local database copy and preserves existing databases; no automated destructive reset is used.


C4 after-sales increment introduces tenant-bound service tickets only for completed projects with accepted new-style delivery review. Ticket collaborators can see only their ticket, not the parent project or full customer. Project managers, scoped supervisors and administrators assign/review/reopen/cancel; the current assignee records work and proposes a resolution. Even an administrator cannot review their own resolution. Serializable command transactions atomically persist ticket, append-only events, idempotency and audit; current identity and scope are rechecked before replay. Open assignments participate in personnel offboarding/department/permission guards. This is internal service management, without SLA automation, attachments, external messages or customer signature. Machine-readable version1.0 contracts are present but no delegated agent/MCP writes are enabled.

C10 stores bounded private evidence bytes in MySQL: 1MiB/file,16MiB retained tenant quota,100 historical records/object. Generic workspace/agent projections never expose the blob; explicit authenticated download validates current identity, parent scope and SHA256 inside a transaction. Upload/withdrawal change parent versions. Task completion, project submission and ticket resolution snapshot active file IDs/hashes. Withdrawals preserve bytes; review/completion freezes mutations. Existing encrypted SQL backups cover metadata and bytes together. Running-disk encryption, malware scanning, larger storage and archival/retention require separate acceptance. Shared command identity validation is extracted unchanged for private reads.

C11 extends sequential approvals with explicit2..8-person all-required stages. ApprovalFlowNode users_all expands into independent runtime nodes sharing one logical order. The current pending anchor identifies the active stage; every pending member of that stage may decide, while future stages stay inactive. A rejection terminates the instance; only all approvals advance. Transferring a vote preserves order/lineage and cannot assign a duplicate current/already-approved voter. Final stage completion, business callback, notifications, event, receipt and audit remain one Serializable transaction. Published snapshots remain immutable. New enum value is appended without rewriting existing records; unsupported older binaries require verified version-matched recovery. Agent approvals, ad-hoc added signers, timeout escalation and reliable external dispatch remain unavailable.
